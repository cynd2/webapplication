# 14. Jenkins Workspace Explanation (Important)

You were confused about paths like:

```
/usr/local/share/myrepo
```

### Important clarification:

Jenkins **automatically creates a workspace**, you do NOT manually create it.

Default workspace:

```
/var/lib/jenkins/workspace/<job-name>/
```

Example:

```
/var/lib/jenkins/workspace/webapplication/
```

Your Git repository will be cloned here automatically when the build starts.

You do NOT need to:

```bash
mkdir workspace
cp files manually
```

---

# 15. Where Your `.deb` File Should Be Generated

Your Jenkinsfile should define where the `.deb` is built, for example:

```
/var/lib/jenkins/workspace/webapplication/build/
```

or

```
/var/lib/jenkins/workspace/webapplication/dist/
```

If your Jenkinsfile expects:

```
/usr/local/share/myrepo
```

You must explicitly create and copy into it inside the pipeline.

# 16. Relationship Between Local Machine, VM, Jenkins, and Git

### Your setup logically works like this:

```
Local PC
  └── GitHub repository (source code + Jenkinsfile)
        ↓
Jenkins (inside VM)
  ├── pulls code from GitHub
  ├── builds .deb
  ├── stores artifact
  └── optionally publishes repo metadata
```

Your **local folder does NOT need to be copied manually into the VM**  
as long as the code is pushed to GitHub.
